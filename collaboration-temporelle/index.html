Chargement…
ICWSM 2026 · pages 1063–1082

Ce qui se répète, au même moment, sur plusieurs gestes

Cette page construit, pour le corpus affiché, le réseau de collaboration décrit par Iannucci, Muratore, Matakos et Kivelä. Deux comptes y sont proches lorsqu’ils font les mêmes gestes, à des instants voisins, et que ces gestes ne sont pas ceux de tout le monde.

Un groupe obtenu ainsi est un signal de coordination. Il peut venir d’une campagne, d’un public qui réagit ensemble, ou d’un événement. Le papier le dit : un analyste doit encore lire ce que ces comptes disent.

La méthode, pas à pas

  1. Quatre couches, séparées. Retweet d’un même message ; hashtag ; mention ; URL externe. Hashtags, mentions et URL sont lus sur les messages propres (original, réponse, citation). Le texte d’un retweet n’est pas recopié sur le retweeteur : ce geste est déjà dans la couche retweet.
  2. Le délai, pas une fenêtre fixe. Pour chaque contenu partagé, on mesure le temps entre un acte de l’un et le prochain acte identique de l’autre, dans les deux sens. Deux actes à la même minute comptent une fois, avec un délai nul.
  3. Le poids de Newman, amorti. Chaque délai ajoute exp(−β × délai) / (n − 1). n est le nombre de comptes distincts qui ont fait ce geste. Un hashtag utilisé par beaucoup pèse peu. β grand ne garde que les actes très proches ; β nul garde toutes les répétitions, quelle que soit l’heure.
  4. β est choisi par les données. Pour chaque couche, on cherche le β entre 0 et 10 qui donne la modularité la plus haute (Leiden, γ = 1). Le délai dans l’exponentielle est en jours, comme dans le code des auteurs : sinon cet intervalle n’a pas de sens.
  5. Les couches ne sont pas additionnées. Un même découpage en groupes est cherché sur les quatre graphes à la fois, en sommant leurs modularités. Un groupe peut donc s’appuyer sur le retweet dans une couche et sur le hashtag dans une autre, sans que les poids, qui ne sont pas sur la même échelle, soient mélangés avant coup.
  6. Le dessin n’est pas la méthode. Les positions viennent d’un ForceAtlas2, pour lire le graphe. La partition, elle, vient de l’étape 5.

La formule

w(u, v) = Σcontenus Σdélais exp(−β · Δt) / (n − 1) Δt en jours. n = comptes distincts sur ce contenu. Un délai au-delà de toute proximité tombe vers zéro quand β augmente.

Ce qui est tenu fixe, et pourquoi

Le papier balaie β de 0 à 10 par pas de 0,01, avec un Leiden à chaque pas. Ici, une grille grosse puis fine classe les β avec 2 itérations de Leiden ; les trois meilleurs du dernier voisinage sont recalculés jusqu’à convergence. À qualité égale, le plus petit β est gardé.

Un contenu partagé par plus de 150 comptes est laissé hors de la somme. Sur un message retweeté des dizaines de milliers de fois, écrire toutes les paires est impossible, et chaque paire pèserait au plus 1/150. Le nombre de contenus écartés est indiqué ci-dessus.

Le papier cite la modularité multi-couches de Mucha et al. (2010), sans donner la force de couplage entre couches. On n’en invente pas une. L’optimisation utilisée (Leiden multiplexe, poids de couche égaux, γ = 1) impose une seule appartenance, commune aux couches, au lieu d’additionner les arêtes. La modularité peut aussi coller une grande part du corpus dans un seul groupe : c’est une limite que les auteurs signalent eux-mêmes.

Si une couche a trop d’arêtes pour l’écran, le tracé garde les plus lourdes. Les groupes, eux, sont ceux du graphe complet sous le plafond de 150 comptes.
